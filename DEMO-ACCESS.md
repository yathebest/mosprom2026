# Доступ коллег к локальному демо

Эти общие реквизиты предназначены для демонстрационного запуска на localhost. Это не доступ к облачному серверу и не учётная запись VPN/Jupyter.

- Адрес: http://127.0.0.1:8765/
- Логин: `demo-admin`
- Пароль: `LinQ-Demo-2026!`
- Роль: администратор всей платформы.

## После клонирования

```powershell
git clone https://github.com/yathebest/mosprom2026.git
cd mosprom2026
git lfs install
git lfs pull
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
.\start-demo.cmd
```

Для CUDA отдельно установите подходящие torch/torchvision по инструкции README. Без CUDA доступен CPU. Для просмотра интерфейса GPU не требуется.

`start-demo.cmd` создаёт демоаккаунт в новой локальной БД и запускает сервер только на 127.0.0.1. Можно отдельно выполнить `python scripts/setup_demo.py`, затем обычный `start.cmd`. Повторное выполнение не сбрасывает пароль, не удаляет записи и не завершает текущие сессии. При конфликте с существующим администратором или логином скрипт останавливается, не расширяя права чужого аккаунта.

Если на вашем локальном стенде уже есть личный администратор и вы намеренно хотите добавить отдельного демонстрационного, используйте `python scripts/setup_demo.py --alongside-existing`. Существующая учётная запись и её пароль сохраняются. Конфликт чужого аккаунта с логином `demo-admin` всё равно блокируется.

После входа откройте «Предприятия» → «Демонстрационное предприятие» → «Открыть пространство». На исходном компьютере прежние видео находятся в предприятии «Локальный проект». У каждого коллеги своя БД: создание предприятия на одном компьютере не создаёт его на других.

Внутри предприятия открывается его рабочая страница с камерами и событиями. Вернуться к управлению платформой можно кнопкой «Кабинет администратора» в панели текущего предприятия. В кабинете у каждой карточки есть «Сотрудники»: добавление, изменение роли, удаление из команды и восстановление, а также количество активных, отключённых и всех сотрудников. Просмотр команды из кабинета не переключает окружение на это предприятие.

## Приглашение администратора предприятия

В деморежиме отправка письма имитируется. «Предприятия» → «Добавить предприятие» → название и email будущего администратора. После создания сайт показывает уникальную ссылку. Откройте её для регистрации: email и предприятие зафиксированы приглашением, роль локального администратора назначается сервером.

Ссылка действует ровно 60 секунд с момента создания. Она одноразовая; повторное приглашение на тот же email в то же предприятие отзывает старую ссылку. Если срок истёк, нажмите «Пригласить администратора» в карточке уже созданного предприятия и отправьте новую ссылку. Новый аккаунт по приглашению использует email как логин.

Письма и токены не коммитятся: они находятся в локальных `data/mail-preview/` и БД. Пока SMTP заморожен; для будущего сервера предусмотрен `mail.example.json` и описание в `docs/admin-invitations.ru.md`.

Общий демонстрационный пароль хранится в Git намеренно, чтобы коллеги могли войти после клонирования. Для сервера создавайте индивидуального администратора через `python scripts/create_admin.py` на отдельной установке и не используйте общий демоаккаунт. Обычный запуск не создаёт его автоматически.
