# Сценарии из задания: реализация и проверка

Основание: «КЕЙС LinQ», слайды 4–9. Каска и респиратор упомянуты как мелкие детали СИЗ на слайде 5. Ниже отделены условия работающего прототипа от того, что ещё нужно подтвердить на целевых данных.

Новые правила подключены к загрузке видео и непрерывному LIVE. Общий путь: модель → сопоставление с человеком/сценой → временное подтверждение → один эпизод → алерт → кадр и клип → журнал → разбор оператором. В payload сохранены модель, найденный класс, bbox, причина и experimental=true. Отсутствие детекции не считается доказательством нарушения.

| Пункт кейса | Что реализовано | Что результат не доказывает |
|---|---|---|
| Бег / резкое перемещение | Скорость по треку, ростов/с либо м/с с калибровкой; выдержка | Порог скорости, не отдельно обученный и оценённый классификатор бега |
| Сближение с техникой | Детектор экскаваторов, wheel loader, грузовиков и других поддержанных классов; IoU-треки; движение техники + близость. Либо операторская область оборудования | Нет отдельного класса вилочного погрузчика. Перспектива ограничивает 2D-оценку; полигон не подтверждает фактическую работу станка |
| Телефон при движении / работе | Более крупный COCO-детектор телефона; сопоставление с рукой по позе; движение человека или область оборудования; выдержка | Предмет рядом с рукой не доказывает разговор/переписку. Скрытая кисть и мелкий телефон дают пропуски |
| Курение / открытый огонь | Отдельные ONNX-детекторы; выдержка; исключение разрешённых областей | Нужен оператор. Сварка, отражения, пар/пыль требуют отрицательных примеров |
| Ограждения | Наблюдаемый переход снаружи внутрь области «За ограждением» | Не различает перелезание, проход и обход. Физическое ограждение задаётся оператором |
| Под грузом / конвейером | Положение ног внутри соответствующего запрещённого полигона, выдержка | Не подтверждает наличие подвешенного груза/конвейера и тип движения «проползание» |
| Высота без страховки | Явный No_Harness, назначенный человеку, плюс полигон «Работа на высоте» | Не измеряет высоту и не проверяет крепление карабина/стропа. Невидимая привязь без отрицательного класса даёт «неизвестно» |
| Падение / лежание | RGB ResNet18 + временные правила; геометрия позы как экспериментальный вариант | Не диагностирует потерю сознания. Независимые P/R/F1=0,90 относятся только к RGB-версии на URFD |
| Неправильная переноска (доп.) | Наклон туловища 40–75°, движение и распознанная сумка/чемодан рядом с рукой | **Частичное покрытие:** промышленные коробки, масса и все нарушения техники переноски не определяются. Нужны целевые данные и дообучение |
| Каска / защита лица / жилет | Прямые классы NO-Hardhat, NO-Mask, NO-Safety Vest + привязка к человеку + выдержка | Mask не доказывает тип/сертификацию респиратора. Неоднозначное сопоставление нескольких людей отбрасывается |

## Настройка на сайте

1. В записи: загрузить видео → шаг «Сценарии» → выбрать нужные пункты. В LIVE: выбрать сценарии в настройках камеры.
2. Получить кадр и разметить полигон, если нужен контекст. Выбрать «Назначение зоны». Семантические зоны не создают дублирующие generic-события.
3. Для привязи обязательна зона высоты; сервер отклоняет запуск без неё. Для телефона можно задать область оборудования. Разрешённые области исключают огонь/курение по центру bbox признака.
4. Камера должна быть неподвижной для анализа движения техники. Без калибровки дистанция приблизительная, в видимых ростах человека. С калибровкой используются метры на выбранной плоскости пола.
5. По умолчанию порог объектов 0,5; выдержка СИЗ 1,5 с, других объектов 1 с. Эти параметры не подбирались по независимому промышленному тесту. Они сохраняются в шаблоне камеры.
6. Алерт и «Видеопроисшествия» содержат новые типы, причину и тайминги. Результат подтверждает/отклоняет оператор.

## Исполнение

Поза и RGB-падения: PyTorch/CUDA на RTX 4060. Дополнительные модели: ONNX Runtime CPU, 4 потока на session. Загружаются только нужные модели. Один PPE-детектор обслуживает каску, жилет, маску и привязь; один fire/smoke — огонь и дым. Телефон повторно анализируется в crop до четырёх крупнейших людей; остальные остаются в общем проходе. Это увеличивает задержку. Несколько потоков конкурируют за CPU.

«До 10 кадр/с» — ограничение отбора LIVE, не обещанная скорость всех моделей. Фактические P95, обработанные/пропущенные кадры показаны в сеансе. На LinQ эти модели пока не запускались. Адаптер должен поддержать configure_scenarios(config) и выдавать objects_state; неподдержанные конфигурации завершаются явной ошибкой без скрытого CPU fallback.

## Данные и качество

Скачан официальный Construction-PPE: 1 416 изображений (1 132 train, 143 val, 141 test), 11 классов. Использован для интеграционных примеров СИЗ. Пересечение с обучением готовых моделей неизвестно: это **не независимый тест наших весов**. Полные изображения есть локально; ZIP решения содержит выбранные примеры. SH17 остаётся кандидатом для следующего цикла обучения, в текущих весах проекта не обучался.

COCO128 использован для технической проверки. На пяти его изображениях с размеченным телефоном общий COCO nano-детектор при пороге 0,5 не нашёл телефон; подключён официальный YOLOv8s и crop-проходы по людям. Это не измерение качества нового детектора.

Примеры огня/курения взяты из репозиториев авторов. Smoking-изображения уже содержат авторские рамки: один пример распознаётся, два не распознаны при стандартном пороге. Это зафиксированное ограничение smoke-проверки.

scenario_e2e.json проверяет реальное исполнение нейросетей, события, отрицательный пример каски и клипы в записи/LIVE. Входы созданы повторением изображений, часть закодирована lossless. Они показывают работу конвейера, **не качество на движущихся независимых видео**. Сжатие и масштаб могут менять отрицательные PPE-классы; это наблюдалось во время проверки.

Для оценки нужны размеченные интервалы на целевых камерах, независимые целые ролики/смены и сложные отрицательные сцены. Отдельно измерять event Precision/Recall/F1, FP/час, пропуски, дубли, задержку тревоги и скорость выбранной комбинации моделей. Новые метрики пока не измерены; >0,95 не заявлено.

## Восстановление весов

ONNX включены в переносимый комплект. Для восстановления:

```powershell
python scripts/download_scenario_models.py
python -m pip install onnx==1.23.2
python scripts/export_scenario_models.py
```

Загрузчик проверяет SHA256; исходные checkpoint остаются в data/cache. Экспорт использует weights_only=True с ограниченным списком известных классов torch/ultralytics; при несовместимости прекращает работу. Произвольный код внешних репозиториев не запускается. Происхождение и хеши — data/models/scenario-manifest.json; атрибуция — THIRD_PARTY.md.


Сквозную проверку можно повторить командой python scripts/check_scenarios.py при запущенном localhost:8765. Она создаёт учебные прогоны/события в журнале и использует включённые в архив выбранные изображения. Физическая камера не открывается. Полные Construction-PPE и COCO128 можно загрузить python scripts/download_scenario_samples.py; это около 187 МБ архивов и больше места после распаковки.
