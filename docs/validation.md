# Фактическая проверка

## Расширение сценариев

58 автоматизированных тестов пройдены. Добавлены проверки неизвестных СИЗ, противоречивых классов, сопоставления с человеком, высоты/привязи, типов зон, телефона/руки/контекста, разрешённых областей огня/курения, движения техники, ограниченного кандидата переноски, серверной проверки моделей и шаблонов камеры. Это проверка логики, не точности нейросетей.

Реальные детекторы проверены через API записи и LIVE; результаты — scenario_e2e.json. Без каски → тревога и клип; каска → без тревоги; No_Harness + учебная зона высоты → тревога; огонь → тревога; LIVE-каска → клип готов до остановки эфира. Входы повторяют выбранные изображения и не являются независимым видеодатасетом. Сжатие меняет ответы PPE-модели, курение распознаётся не на всех авторских примерах. Подробности и ограничения — scenarios.ru.md и JSON-отчёты smoke-проверок. Основной fall-test не менялся.

## Качество падений

Финальная проверка выполнена на 20 заранее отложенных целых последовательностях URFD: fall21–30 и adl31–40. Обучение: fall01–15, adl01–25. Validation: fall16–20, adl26–30. RGB-вход 224×224; depth-признаки и акселерометр не использованы как вход модели. CSV-метки использованы только для обучения/оценки.

ResNet18 с ImageNet-инициализацией обучался 18 эпох. Сохранена эпоха 4 по validation frame F1 при пороге 0,5. Рабочая точка временных событий выбрана затем на validation: probability 0,90, выдержка 0,5 с, максимальный переход от уверенного вертикального состояния 1 с. Validation event F1 = 1,00; это данные подбора, не независимая оценка.

Независимый test: **TP 9, FP 1, FN 1; Precision 0,90, Recall 0,90, F1 0,90**. Пропуск fall21, ложная тревога adl35. Параметры после этого по данным test не менялись. Кадровые показатели: TP152, FP0, FN192; Precision1,00, Recall0,44186, F1 0,61290, 818 оценённых кадров. Переходные/неопределённые метки исключены только из кадровой оценки.

Около 92 с обычных действий дают 1 ложную тревогу, формально 39,19/ч; такой короткий материал недостаточен для устойчивой часовой оценки. Оценка по участникам/промышленным камерам не выполнена. Показатели других сценариев не измерены. Цель >0,95 **не достигнута**.

`quality_report.json` содержит все предсказания и ошибки. Точные совпадения повторного воспроизведения сохранённых вероятностей подтверждены при добавлении live-функций; обучения/подбора на test не было. Хеши классификатора, весов и Rules.step позволяют обнаружить устаревшую оценку.

## Приложение

- 39 базовых проверок (до расширения до 58): временные подтверждения/перевзвод, окклюзии, подавление дублей, восстановление ID, нормализованные/метрические скорости, ошибки полигонов, валидация файлов/источников, БД/фильтры/CSV, операторские статусы, очередь и ZIP-разметка, latest-frame ingest, защита URL камеры от экспорта.
- Статическая проверка синтаксиса Python и JavaScript.
- Браузером пройдено: учебное видео → сценарии → зона → запуск → клип → подтверждение оператором; live-источник → просмотр/алерт → архив; статистика и качество.
- Файл fall01 с зоной и RGB-моделью: 2 разных события (зона и падение), 41,35 обработанных кадра/с, P95 инференса 28 мс на локальной RTX 4060. Это короткий smoke-прогон, не качество на тесте и не TPU-результат.
- `live_smoke.json`: два ограниченных HTTP-сеанса, по100 обработанных кадров; 1 тревога падения / 0 на нормальном действии, P95≈25,5 мс.
- `continuous_live_smoke.json`: два непрерывных HTTP MJPEG-потока одновременно, алерты и самостоятельное сохранение примерно7-секундных H.264-клипов, пока источники ещё работали. Остановка сохраняет хвостовой клип с признаком неполноты. Источник — повтор обучающего видео для проверки механики, не новый accuracy benchmark.
- `body_onnx_smoke.json`: ONNX ResNet18 opset12, вход1×3×224×224, выход1×2; 6 реальных обучающих кадров, максимальное расхождение логитов с PyTorch <2×10⁻⁶, проверены высокий/низкий выходы. YOLO ONNX отдельно в `onnx_smoke.json`.

## Незакрытые проверки

1. LinQ SDK недоступен по внешним ссылкам; VPN-переключение отложено пользователем. Компиляция TPU-программы, реальный API, качество после квантования и измерения LinQ **не выполнены**.
2. Физические камеры/USB и реальные RTSP-источники не испытывались. Есть проверка HTTP MJPEG и API приёма кадров устройства. Браузерное разрешение на камеру должен дать пользователь.
3. Нет промышленного датасета для подтверждения >0,95 и остальных паттернов.
4. Непрерывный live пока без автоматического переподключения, производственного мониторинга и политики хранения. Видео сохраняются локально; для длительной эксплуатации нужны дисковые лимиты.
