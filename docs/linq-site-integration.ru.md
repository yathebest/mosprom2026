# Подключение сайта к сервису LinQ TPU

Интеграция набора `linq-integration-kit.zip` в текущую версию приложения,
25 октября 2026 года. Входной PROMPT рассматривается как задание пользователя;
описанные в нём замеры стенда отделены от проверок, выполненных в этой установке.

## Состав и границы исполнения

- На удалённом TPU выполняется head нашей person-YOLO12m. Протокол организаторов:
  RabbitMQ `10.0.114.30:5672`, exchange `tpu.direct`, routing key `input`, PyTask.
- URI сохранён: `file:///auto/cache/hackathon74291/person-yolo12m-head-b1-o1-h1m.tpu?v=2&raw=False`.
  Версия входит в ключ кеша сервиса. При фактической замене программы версию следует
  согласованно изменить в адаптере и резервном ноутбуке.
- Decode/NMS, трекинг, временные состояния и правила остаются на хосте.
- Поза YOLOv8n-pose также вычисляется на хосте. Она дополняет рамки TPU ключевыми
  точками для подтверждения ID и проверки рук/головы/торса. Самостоятельные рамки
  локальной pose-модели не подменяют детекцию людей на TPU.
- Выбранные СИЗ/телефон/огонь/дым/курение считаются локальными ONNX-моделями.
  RGB ResNet18 включается только для выбранных сценариев падения и выключается
  переменной `LINQ_FALL_ONNX=0`. Это гибрид, а не перенос всех моделей на TPU.
- Вызов `predict` последовательный. Плавность видеопросмотра не равна частоте
  нейросетевого анализа; новый FPS или гарантированная задержка не заявляются.

Защита текущего трекера от ложных ID сохраняется: перед публикацией ID нужны
несколько свежих наблюдений и семантическое подтверждение. Одна уверенность
детектора не отменяет эти проверки. Если лицо/поза неразличимы, человек может
остаться кандидатом. Качество на конкретной камере требует самостоятельной оценки.

## Установка

Из корня проекта, в том же Python-окружении, в котором запускается сайт:

```powershell
python -m pip install -r requirements-linq.txt
python scripts/install_linq_runtime.py /path/to/tpu_pycloud_format.zip
python -c "import pika, tpu_pycloud_format; print('LinQ dependencies OK')"
```

Папка `tpu_pycloud_format/` из предоставленного набора должна находиться рядом
с `my_linq.py`. Это оригинальный сериализатор организаторов, он не публикуется
в Git. В этой установке пакет уже скопирован. В новой копии репозитория его
следует установить из исходного integration kit или отдельного
`tpu_pycloud_format.zip` указанной выше командой, сохранив все файлы пакета.
Пакет и `linq-timing.json` добавлены в `.gitignore`; TPU-файлы уже исключены.
Полная инструкция клонирования, Git LFS, Python, создания аккаунта и запуска
на Windows/Linux находится в [README](../README.md#запуск-из-git-на-linq-tpu-организаторов).

Для обычного режима по-прежнему используется `start.cmd` без `LINQ_ADAPTER`.

## Проверки без VPN

```powershell
python scripts/repro_linq_adapter.py
python scripts/verify_linq_decode.py
python -m pytest -q
```

Первая команда изолирует SQLite и медиа во временной папке, создаёт тестового
пользователя, загружает короткую запись и проходит настоящий конвейер приложения:
адаптер, трекер, событие опасной зоны, экспорт клипа и отчёт. Транспорт и поза в
этой проверке заморожены. Отсутствующий в исходном наборе
`work/linq-check/reference-yolo12m.npz` больше не требуется. В конце:

```text
OK: site pipeline works end-to-end with the LinQ adapter (mocked transport)
```

Вторая команда требует локальные `onnx` и `onnxruntime`, совпадающий
`data/models/person-yolo12m.onnx` и включённый открытый URFD-пример. Она сравнивает
неизменённую numpy-формулу из набора с реальным ONNX-хвостом, сохраняет эталон и
отчёт в `data/cache/linq-offline/`. Это FP32-паритет, не качество INT8 и не TPU.

## Запуск с настоящим сервисом

1. Подключите VPN команды. Необходимо, чтобы `10.0.114.30:5672` был доступен.
2. Остановите текущий экземпляр сайта, занимающий порт 8765.
3. Запустите `start-linq.cmd`. Он использует `.venv\Scripts\python.exe`, если
   такое окружение есть, иначе `python` из PATH.

```cmd
start-linq.cmd
```

Командный логин по умолчанию — `hackathon74291`, программа —
`person-yolo12m-head-b1-o1-h1m.tpu`. В startup выполняется пробный запрос.
Только при сопоставленном ID ответа, `status_code=0`, PID воркера и корректных
выходных тензорах появляется строка:

```text
[LinQ] подтверждено удалённым воркером: pid=... status_code=0 roundtrip=...ms
```

Затем откройте `http://127.0.0.1:8765/` и запустите анализ записи или эфир.
В отчёте имя backend начинается с `LinQ TPU / person-yolo12m...`, после чего
перечисляются локальные компоненты. `/api/health` содержит `linq_verified` и
`linq_status` с последним проверенным ответом. Наличие переменной окружения
или офлайн-проверка сами по себе не устанавливают `linq_verified=true`.

При недоступности брокера startup завершается ошибкой. Автоматического перехода
с детекции TPU на локальную person-модель нет. Сетевые ожидания ограничены,
временная очередь ответа эксклюзивна, соединение закрывается и при ошибке.

Время `roundtrip_ms` включает клиентский сетевой оборот. Оно не является чистым
временем ядра TPU. Показатель last_reply — свидетельство последнего ответа,
а не непрерывный мониторинг доступности брокера между запросами.

## Артефакты и происхождение

| Артефакт | Значение |
|---|---|
| Исходный person ONNX из PROMPT, совпал с локальным | `b92dd8b59bf461d1463e32333eb0e63135857699054bccc5a0057222d00c33fe` |
| Фактический SHA256 `.tpu` из приложенного ZIP | `37281bff05117d546f1bb76d4431c41b8e7e00a88c46a16578e46e19b918cc95` |
| Резервная программа | `data/linq/person-yolo12m/person-yolo12m-head-b1-o1-h1m.tpu` |
| Резервный ноутбук | `notebooks/stand-linq-check.ipynb` |

В исходном описании указан другой SHA `.tpu`; в проект скопирован именно
бинарный файл из ZIP с приведённым выше фактическим SHA, без подмены стоковым
COCO-комплектом. SHA фактической удалённой программы ответ воркера не сообщает.
Удалённый cache-path и версия v2 сохранены по инструкции поставленного набора.

Авторы набора сообщают о предыдущем аппаратном запуске. Сам архив не содержит
`linq-timing.json`/`linq-hardware-timing.json` с измерениями, а ячейки ноутбука
поставлены без сохранённых outputs. Поэтому предыдущие значения p50 не выдаются
за результат проверки этой установки. Новый отчёт находится в
`docs/linq-integration-verification-20261025.json`.

## Резервный ноутбук

В этой задаче ноутбук на стенде не запускался, программа не перезагружалась.
Ноутбук нужен только если организаторы удалят программу. В нём синхронизирован
URI v2 и добавлена проверка SHA резервного `.tpu`. Автоматическое удаление и
переустановка numpy из исходной диагностической ячейки заменены проверкой без
изменений среды. Для реальной перезагрузки также нужен тестовый кадр
`test-person.jpg`; сравнение с NPZ опционально. Имена эталонов должны соответствовать
текущей person-модели, а не стоковой COCO-модели.

## Перенос на другую машину

Клонируйте репозиторий, выполните `git lfs pull`, установите зависимости и
библиотеку из предоставленного ZIP по инструкции README. Рабочие PT/ONNX-веса
распространяются через Git LFS. Программа уже должна
находиться в cache сервиса под командным логином. Локальный `.tpu` нужен как
резерв, он не загружается адаптером автоматически. SDK-компиляция и сервисная
сериализация — разные зависимости; SDK для обычного удалённого инференса
клиенту не требуется. БД, VPN-ключи и приватные записи в Git не добавляются.
