# Доступность сценариев в интерфейсе

Источник правил новых запусков — авторизованный `GET /api/patterns`. Решения о конкретных сценариях находятся на сервере, а не зашиты в браузер. Поддерживаемый контракт: версия, список `patterns` с `enabled/config_flag/event_kinds/zone_kinds`, `enabled_flags`, `disabled_flags` и `enabled_zone_kinds`.

Каталог загружается до показа рабочего пространства. Запрещённые карточки и чекбоксы физически удаляются из нового анализа и LIVE, вместе с относящимися к ним параметрами, окнами подтверждения и вариантами назначения зон. Пустая группа дополнительных сценариев убирается целиком. Место удалённого сценария не занимает карточка «скоро». Зеркальная область сохраняется как контекст, если она разрешена сервером.

Конфигурация повторного анализа, клона, шаблона и нового источника проходит клиентскую очистку: отключённые флаги становятся `false`, неподдерживаемые типы зон и окна удаляются из новой копии. Исходный объект истории не мутируется. Для ранее сохранённого шаблона показывается сообщение об исключении недоступных правил. Сериализация обоих режимов повторяет очистку перед запросом, поэтому старое значение в defaults или шаблоне не включает скрытый сценарий.

Сервер отдельно отклоняет запрещённые новые настройки при сохранении камеры и старте файла/эфира. Клиентская фильтрация не заменяет эту проверку. Ответ `disabled_patterns` отображается через человекочитаемое `detail.message`, а не как строка `[object Object]`. Если каталог недоступен, новая настройка блокируется и требует повторной загрузки страницы.

Учебные примеры берутся из разрешённых сервером `pattern_ids`; отсутствующие файлы не отображаются как неработающие кнопки. Справка перечисляет текущие разрешённые сценарии. Старые отчёты качества явно отделены от доступности новых запусков.

Исторические события, названия сценариев, фильтры журнала/клипов, видеодоказательства и результаты проверки оператора сохранены. Изменение каталога не удаляет историю. Решение о текущем разрешённом наборе не является заявлением независимых метрик нейросети.

Проверки включают очистку старого шаблона без изменения оригинала, сохранение контекста зеркала, запрет неподдерживаемых окон, физическое удаление DOM-контролов при сохранении исторических селекторов и отсутствие обхода через учебный пример. Конкретный окончательный набор определяется матрицей практической проверки и серверным manifest.
