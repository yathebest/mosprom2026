# Предприятие и приглашение его администратора

В разделе «Предприятия» у администратора платформы есть «Добавить предприятие». Он задаёт название, описание и email будущего локального администратора. Предприятие сразу создаётся активным, а получатель регистрирует личный аккаунт по приглашению. Публичная заявка предприятия по-прежнему доступна отдельным сценарием и требует одобрения.

В карточке любого активного предприятия можно пригласить дополнительного администратора или выпустить новую ссылку на прежний email. Локальный администратор и остальные роли не имеют права пользоваться этими методами платформы.

## Локальная демонстрация

Отправка по умолчанию имитируется; SMTP пока заморожен. Окно результата показывает email, ссылку, обратный отсчёт, кнопки копирования и открытия регистрации. Настоящие письма не отправляются. Письмо сохраняется в `data/mail-preview/`; просмотр доступен только администратору платформы. Каталог исключён из Git и не публикуется через `/media`.

1. Войдите как `demo-admin` (см. `DEMO-ACCESS.md`).
2. «Предприятия» → «Добавить предприятие» → имя и email → создание.
3. Скопируйте ссылку и откройте до истечения минуты. Для проверки отдельного пользователя удобно использовать приватное окно того же браузера на этом компьютере.
4. Получатель видит зафиксированные email и предприятие, задаёт имя и пароль. Email становится его логином. Роль `enterprise_admin` устанавливается сервером, а не формой.
5. По завершении регистрации ссылка погашается. Человек уже вошёл и может управлять своим предприятием.

Если открыть регистрацию в обычном окне на том же origin, после успешного создания аккаунта текущая сессия этого окна заменится сессией нового администратора. Для возврата администратора платформы нужно выйти и войти заново.

## Срок и одноразовость

Срок — 60 секунд с генерации, проверяется серверным временем при просмотре и при регистрации. Клиентский таймер информационный; изменение часов компьютера или HTML не продлевает доступ. Пароль хешируется до окончательного повторного контроля срока: если минута истекла за это время, аккаунт не создаётся.

Каждая отправка использует новый случайный 256-битный токен; в таблице `admin_invitations` хранится только SHA256 токена. Предыдущие ещё не использованные ссылки для пары «предприятие + email» немедленно отзываются. Регистрация и погашение ссылки проходят в одной транзакции; две одновременные попытки создадут только один аккаунт.

Адрес имеет вид `/#invite=...`: fragment не передаётся в HTTP-запрос страницы, серверные access logs или referrer. После чтения сайт удаляет fragment из адресной строки. Обновление страницы теряет временную форму — нужно повторно открыть исходную ссылку, пока она действительна. Предпросмотр не погашает приглашение; успешная регистрация погашает.

Токен привязан к email и предприятию. Подмена role, email или organization_id при регистрации запрещена строгой схемой запроса. Просроченная, использованная, заменённая ссылка и ссылка на приостановленное предприятие получают HTTP 410. Ошибка отправки отзывает приглашение; открывать его нельзя. Если предприятие уже было создано перед ошибкой доставки, повторное приглашение делается из его карточки.

Если email уже занят аккаунтом, приглашение не переносит и не повышает существующего пользователя. Текущее ограничение — один аккаунт относится к одному предприятию; для многофирменного членства нужна отдельная модель membership.

## SMTP на будущем сервере

1. Скопируйте `mail.example.json` в `data/mail.local.json` и укажите `mode: smtp`, host, port, security (`starttls` или `ssl`), username, password, from_address, public_url.
2. Для `public_url` укажите внешний HTTPS origin без пути; localhost допустим только для проверки на том же компьютере. Ссылка с 127.0.0.1 в письме на другом компьютере откроет localhost получателя, а не ваш сервер.
3. Поддерживаются переменные `SAFETY_MAIL_MODE`, `SAFETY_MAIL_HOST`, `SAFETY_MAIL_PORT`, `SAFETY_MAIL_SECURITY`, `SAFETY_MAIL_USERNAME`, `SAFETY_MAIL_PASSWORD`, `SAFETY_MAIL_FROM_ADDRESS`, `SAFETY_MAIL_PUBLIC_URL`. Они имеют приоритет над локальным файлом. `start-demo.cmd` принудительно выбирает preview; для SMTP запускайте обычный сервер.
4. Настройки читаются при отправке. Секреты не возвращаются в API и не включаются в журнал. `data/mail.local.json` исключён из Git. Все отправки используют проверку TLS-сертификата, SSL либо STARTTLS; незашифрованный SMTP не поддерживается.
5. Срок 60 секунд начинается до передачи SMTP. Задержка почтового провайдера съедает этот срок; успешный ответ SMTP не гарантирует доставку во входящие. Если письмо пришло поздно, администратор отправляет новую ссылку. По текущему требованию срок не увеличивается автоматически.

Реальная отправка и её доставляемость пока не проверены: домена и SMTP-реквизитов нет. Проверены имитация и SMTP-транспорт на тестовой заглушке, без сетевой отправки.

Основные методы: POST `/api/platform/organizations`, POST/GET `/api/platform/organizations/{id}/invitations`, POST `/api/invitations/inspect`, POST `/api/invitations/accept`. Публичные методы принимают токен в JSON, не в query string. Они ограничены по частоте, отклоняют cross-origin изменения и не принимают роль/предприятие из пользовательского ввода.
