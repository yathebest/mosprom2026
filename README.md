# LinQ Safety

Репозиторий: https://github.com/yathebest/mosprom2026. Основная локальная папка: `C:\Users\User\Desktop\mosprom2026`.

Весовые файлы хранятся в Git LFS. После клонирования установите Git LFS и выполните `git lfs pull`; без загрузки реальных весов вместо LFS-указателей детекция работать не будет. В Git входят код, модели, выбранные открытые учебные примеры и документация. Локальная БД, записи/клипы камер, полные датасеты, кеши и учётные данные исключены.

Локальное приложение промышленной видеоаналитики с двумя режимами: непрерывный прямой эфир с камеры и анализ загруженных записей. Базовые сценарии: опасная зона, быстрое перемещение, возможное падение и длительное лежание. Добавлены экспериментальные детекторы касок/СИЗ, телефона, огня/дыма, курения и техники, а также зоны ограждений, груза, конвейера и высоты. Точные условия и ограничения каждого сценария — в `docs/scenarios.ru.md`.

**Статус:** локальная реализация и проверки готовы; обязательный запуск на LinQ TPU ещё не выполнен. Цель качества >0,95 не достигнута: независимый тест падений дал Precision = Recall = F1 = 0,90. Подробности и все ограничения — в `docs/validation.md` и интерфейсе «Качество модели».

## Запуск

Откройте `start.cmd`, затем http://127.0.0.1:8765. На этом компьютере поза и падения используют RTX 4060 Laptop 8 ГБ / PyTorch CUDA; дополнительные ONNX-детекторы выполняются на CPU. Включение всех моделей и crop-проходов телефона увеличивает задержку. Фактические P95 и число обработанных кадров показаны в каждом сеансе. VPN для локального режима не нужен. Секреты стенда в проект не входят.

На чистом компьютере нужен Python 3.11–3.13:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts/download_model.py
python -m uvicorn app.server:app --host 127.0.0.1 --port 8765
```

Для NVIDIA установите совместимые torch/torchvision по официальному [PyTorch installer](https://pytorch.org/get-started/locally/). Без CUDA доступен CPU, скорость будет другой. Обученные веса классификатора падений включены в локальный комплект.

## Два режима

**Прямой эфир.** Откройте «Прямой эфир», выберите RTSP/HTTP-камеру либо веб-камеру/USB-устройство, укажите название и правила, начните эфир. Для устройства браузер запросит разрешение; аудио не запрашивается. На localhost поддерживается безопасный контекст браузера. Если встроенный браузер не предоставляет устройства, используйте Chrome/Edge.

Для зон сначала получите кадр. Открытый блок «2. Зоны на кадре» показывает сам кадр, число выбранных точек, назначение и сохранённые полигоны. Отметьте минимум три вершины и нажмите «Сохранить зону»: правило включится автоматически. Кнопка «Разметить зоны на кадре» переводит прямо к редактору. Камеру предпросмотра можно сразу отключить отдельной кнопкой — статический кадр остаётся для разметки, запуск эфира не требуется. Отмена незавершённого запроса камеры и ошибки воспроизведения освобождают полученные медиатрэки.

Изображение с детекцией показывается через MJPEG. Входная очередь хранит только последний кадр, чтобы обработка не накапливала старые кадры. Анализ ограничен примерно 10 кадрами/с; пропуск промежуточных кадров ожидаем. Эфир работает до остановки или потери источника. Доступны два одновременных эфира. Это не испытание промышленной отказоустойчивости; автоматического переподключения нет.

При событии появляется алерт с паттерном, камерой, временем получения кадра и таймингами от начала эфира. Буфер сохраняет 3 секунды до тревоги и 4 после; экспорт H.264 идёт отдельно, эфир продолжает работать. В «Видеопроисшествиях» видны состояния записи/экспорта/готовности, фильтры и скачивание MP4. При ранней остановке сохраняется доступная часть клипа с явной пометкой.

**Анализ записей.** Загрузите видео или выберите учебный URFD-пример. Пройдите четыре шага: источник, сценарии, зоны, проверка. После анализа доступны размеченное видео, клипы, события и JSON-отчёт. До двух файлов анализируются параллельно. Видеофайлы должны иметь постоянный FPS; лимиты — 500 МБ, 4K, 60 минут.

## Качество и границы применимости

URFD: скачаны 70 последовательностей (30 падений, 40 обычных действий), RGB-половины авторских превью. Разделение заранее зафиксировано: 40 обучение / 10 выбор настроек / 20 итоговый тест. Кадры одного ролика не пересекаются между частями. Независимость по участникам подтвердить нельзя. Это бытовые сцены 320×240, не промышленный тест.

На финальном тесте: 9 TP, 1 FP, 1 FN; event Precision/Recall/F1 = 0,90. На отдельных размеченных кадрах: Precision = 1,00, Recall = 0,442, F1 = 0,613. Метрики относятся только к указанной версии модели и сценарию падения. Уверенность кадра, FPS и доля подтверждений оператором не заменяют качество распознавания.

RGB-классификатор оценивает всю сцену, не назначает лежащего конкретному человеку и не доказывает причину падения. Нужны дополнительные данные с целевых камер, разные участники/ракурсы и сложные отрицательные примеры. Для новых сценариев добавлены модели и временные правила, но независимое качество не измерено. Переноска покрыта частично: только сильный наклон с распознанной ручной кладью. Реальная высота, масса груза, произвольные коробки и правильность крепления страховки не определяются.

Метрическая скорость корректна только для неподвижной камеры и выбранной плоскости пола. Без калибровки показывается относительная скорость в видимых ростах/с. Это не отдельный проверенный классификатор бега. При сильном перекрытии трекер может ошибиться; гарантии устойчивой идентичности нет.

Лайв проверен на двух локальных HTTP MJPEG-источниках. Физическая веб-камера и реальные RTSP-камеры отдельно не испытаны. Время live-события основано на времени получения кадра сервером; задержка самой камеры и сети отдельно не измерена.

## Проверки и воспроизведение

```powershell
python -m pytest -q
node --test tests/test_camera_preview.cjs
python scripts/prepare_urfd.py --all
python scripts/export_onnx.py --opset 12 --size 640
python scripts/export_body_onnx.py
```

Скрипт подготовки загружает авторские MP4 и CSV-аннотации, выделяет RGB. Полный набор есть локально; переносимый ZIP содержит четыре демо и манифест, остальное можно скачать.

Исходное обучение: `python scripts/train_fall_classifier.py --epochs 18`. Существующие оценённые веса защищены от случайной перезаписи; для нового эксперимента используйте копию проекта. Выбор порогов: `python scripts/evaluate_fall.py --split validation`. Итоговый тест запускается `--split test` один раз и отказывается молча перезаписывать существующий отчёт. Новый эксперимент требует нового независимого теста; нынешние 20 роликов уже раскрыты.
