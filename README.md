# LinQ Safety

## Состояние по критериям кейса — 25 октября 2026

Репозиторий содержит работающий локальный прототип и адаптер удалённого LinQ.
**Полное выполнение всех критериев пока не подтверждено.** Матрица требований:
[docs/coverage.json](docs/coverage.json); подробный аудит:
[docs/repository-criteria-audit-20261025.json](docs/repository-criteria-audit-20261025.json).

| Критерий оценки | Фактическое состояние |
|---|---|
| Прототип | LIVE, анализ записей, тревоги, клипы и история реализованы; отдельный клон прошёл офлайн-проверку |
| Решение основной проблемы | Есть успешные проверки выбранных видео; по промышленным падениям, курению и отсутствию сигнальной одежды сохраняются пропуски |
| Разработка и внедрение | Есть инструкция Windows/Linux, веса в Git LFS и установщик протокола; замеры LinQ, нагрузка на целевом числе камер и расчёт стоимости внедрения ещё нужны |
| Новаторские идеи | Контекстные клипы, объединение доказательств нескольких нарушителей, аналитика и экспорт; сравнительная уникальность не доказана |
| UI/UX | Есть проверки интерфейсной логики и предыдущие проверки через UI; отдельное пользовательское исследование не проводилось |
| Второстепенные проблемы | Реализованы подавление повторов, временные состояния ID, правила зон, права доступа и два одновременных эфира |
| Аналитика | Дашборд и экспорт реализованы; исследование аудитории, сравнение аналогов и измерение эффекта внедрения требуют дополнения |

В обязательных требованиях остаётся **реальный инференс на LinQ с замерами**:
офлайн-проверка использует подменённый транспорт. Слайд 13 кейса разрешает
выбирать приоритетные сценарии, поэтому реализация всех восьми примеров не
является обязательным единым перечнем. Текущие 12 включённых типов сценариев
и четыре отключённых задаются `app/pattern-policy.json`.

Цель P/R/F1 >0,95 поставлена пользователем; в слайде 13 такого численного
порога нет. Исторические P/R/F1=0,90 на URFD относятся к прежнему конвейеру.
Независимая общая точность текущих моделей на заводских камерах не измерена.
Два испытанных потока не подтверждают масштабирование на всё предприятие.

Последний прогон: **331 Python-тест и 110 JS-тестов прошли**. Эти проверки
подтверждают логику приложения; отдельная оценка качества моделей отражена в
отчётах видео и исторических метриках.

## Запуск из Git на LinQ TPU организаторов

Сайт можно запустить на Windows или Linux и подключить к удалённому сервису
LinQ. На TPU исполняется head обученной **person-YOLO12m**. Decode/NMS, поза,
трекинг, СИЗ, телефон и остальные правила выполняются на компьютере с приложением.
Наличие NVIDIA GPU на этом компьютере не обязательно; производительность
локальных сценарных моделей зависит от его ресурсов. Это гибридный режим.

**Что потребуется:** Git + Git LFS, Python (локально проверен 3.13.9), доступ
к VPN команды и выданный организаторами `tpu_pycloud_format.zip` либо
`linq-integration-kit.zip`. По заданию `PROMPT.md` библиотека организаторов и
`.tpu` не публикуются в Git. Поэтому одного `git clone` без предоставленной
библиотеки недостаточно. Все рабочие PT/ONNX-веса распространяются через Git LFS;
обучать и компилировать модели заново для запуска не нужно.

### 1. Клонировать проект и загрузить веса

```shell
git lfs install
git clone https://github.com/yathebest/mosprom2026.git
cd mosprom2026
git lfs pull
git lfs fsck
```

Не используйте GitHub «Download ZIP» вместо клонирования с Git LFS: в таком
архиве могут оказаться указатели вместо весов.

### 2. Установить зависимости и библиотеку организаторов

Windows PowerShell:

```powershell
py -3.13 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\python.exe -m pip install -r requirements-server.txt -r requirements-linq.txt
.venv\Scripts\python.exe scripts/install_linq_runtime.py "C:\path\tpu_pycloud_format.zip"
.venv\Scripts\python.exe -c "import pika, tpu_pycloud_format; print('LinQ dependencies OK')"
.venv\Scripts\python.exe scripts/server_preflight.py
```

Linux, из корня клона:

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements-server.txt -r requirements-linq.txt
python scripts/install_linq_runtime.py /path/to/tpu_pycloud_format.zip
python -c "import pika, tpu_pycloud_format; print('LinQ dependencies OK')"
python scripts/server_preflight.py
```

Вместо `tpu_pycloud_format.zip` установщик также принимает полный
`linq-integration-kit.zip`. Он извлекает только пять файлов протокола в
`tpu_pycloud_format/`, не запускает содержимое архива и не перезаписывает
отличающуюся установленную версию. Архив и установленную папку в Git не добавляйте.
Команды выше устанавливают PyTorch CPU для локальных компонентов; готовую
совместимую CUDA-установку заменять не требуется.

### 3. Создать вход в приложение

На новой установке выполните в том же Python-окружении:

```shell
python scripts/create_admin.py
```

Задайте логин, имя и пароль администратора платформы. На Windows без активации
окружения используйте `.venv\Scripts\python.exe` вместо `python`.
Для общего локального демо можно вместо этого выполнить
`python scripts/setup_demo.py`: вход `demo-admin` / `LinQ-Demo-2026!`.
Учётная запись приложения отличается от VPN/Jupyter и командного логина LinQ.
После входа создайте предприятие и откройте его рабочее пространство;
демо-команда создаёт «Демонстрационное предприятие» автоматически.

### 4. Подключить TPU и запустить сайт

Подключите VPN команды на машине, где запущен Python. Брокер организаторов
`10.0.114.30:5672` должен быть доступен. Для сервера внутри их сети достаточно
сетевого маршрута к брокеру; устанавливать VPN в таком случае не требуется.
Остановите другой экземпляр сайта, если он занимает порт 8765.

Windows:

```powershell
.\start-linq.cmd
```

Linux, с активированным `.venv`:

```bash
export LINQ_ADAPTER=my_linq:create_backend
export LINQ_LOGIN=hackathon74291
export LINQ_PROGRAM=person-yolo12m-head-b1-o1-h1m.tpu
python -m uvicorn app.server:app --host 127.0.0.1 --port 8765
```

Используется программа сервиса
`/auto/cache/hackathon74291/person-yolo12m-head-b1-o1-h1m.tpu?v=2&raw=False`.
Командный логин менять не нужно. По предоставленному набору программа уже
загружена на стенд: обычный запуск не требует Jupyter, SDK или повторной компиляции.
При удалении программы организаторами используйте резервный ноутбук и `.tpu`
из integration kit: [подробная инструкция](docs/linq-site-integration.ru.md).

Откройте [http://127.0.0.1:8765/](http://127.0.0.1:8765/), войдите и запустите
«Анализ записей» или «Прямой эфир». Для приложения на удалённом Linux-сервере
оставьте bind на localhost и пробросьте порт с рабочего компьютера:

```shell
ssh -L 8765:127.0.0.1:8765 user@server
```

Тогда сайт открывается на том же localhost рабочего компьютера. Для веб-камеры
используйте Chrome/Edge и разрешите доступ к камере.

### 5. Убедиться, что используется TPU

При запуске адаптер отправляет настоящий пробный запрос. Ожидаемая строка:

```text
[LinQ] подтверждено удалённым воркером: pid=... status_code=0 roundtrip=...ms
```

В [http://127.0.0.1:8765/api/health](http://127.0.0.1:8765/api/health)
проверьте `linq_verified: true` и `linq_status.last_reply_at`. После анализа
видео поле модели в отчёте должно начинаться с `LinQ TPU / person-yolo12m...`.
При недоступности TPU приложение завершается с ошибкой запуска и не подменяет
детектор людей локальной моделью. Обычный `start.cmd` запускает локальный режим.

| Проблема | Действие |
|---|---|
| Нет `tpu_pycloud_format` | Выполнить установщик из шага 2 с предоставленным ZIP |
| Нет весов / вместо модели текст `version https://git-lfs...` | Выполнить `git lfs pull`, затем `git lfs fsck` |
| `LinQ TPU недоступен` | Проверить маршрут/VPN к `10.0.114.30:5672`; на Windows — `Test-NetConnection 10.0.114.30 -Port 5672` |
| Воркер сообщает об отсутствии программы | Восстановить программу из integration kit резервным ноутбуком; не менять логин произвольно |
| Порт 8765 занят | Остановить предыдущий экземпляр приложения |

Офлайн-проверка без VPN: `python scripts/repro_linq_adapter.py`. Она проверяет
конвейер с подменённым транспортом и **не подтверждает аппаратный запуск**.
В этой установке прошли офлайн-проверка и 331 Python-тест; настоящий брокер на момент
проверки был недоступен. Нового аппаратного замера пока нет.
Контракт, фактические SHA и состояние проверок —
[руководство по интеграции](docs/linq-site-integration.ru.md).

## Усиление детекции и обучение на Kaggle

Новый конвейер отделяет обнаружение человека от позы. При наличии `data/models/yolo12m.pt` используется независимый YOLO12m вместе с pose-моделью. Дообученный `person-yolo12m.pt` работает совместно с исходным COCO-детектором: рамки объединяются с подавлением дублей. Получить исходные веса: `python scripts/download_model.py`.

Обученный пакет Kaggle 361639587 установлен на локальном стенде. Для установки другого архивного комплекта используйте команду `python scripts/install_trained_models.py "C:\path\linq-night-trained-models.zip"`. Установщик проверяет ONNX-графы, классы и политику crop, сохраняет прежние файлы и устанавливает модели людей, касок, жилетов и два ResNet50-классификатора. Текущие рабочие веса теперь хранятся в Git LFS; архивный установщик остаётся способом установки другого обученного комплекта. Фактические метрики обучения — `docs/trained-model-metrics.json`, проверка подключения — `docs/trained-deployment.json`.

При наличии `data/models/fall-temporal.pt` дополнительно включается обученный ResNet18/GRU. Его временное окно формируется по таймингам исходных кадров; вероятность падения не подменяет вероятность положения тела. Для тревоги нужен также признак позы или RGB-модели. Подключение действует и для записей, и для LIVE. Независимые event-метрики нового объединённого конвейера пока не измерены.

Трекинг сохраняет слабое реальное наблюдение и кратко показывает последнюю рамку при пропуске до 0.5 с. Такие рамки явно помечаются и не подтверждают новые нарушения; прогноз сбрасывает незавершённое подтверждение. В типах зон добавлено «Зеркало»: исключается размеченная область положения ног отражения, а не любой bbox, пересекающий зеркало. Разметка зависит от конкретной камеры.

Каски/жилеты проверяются на целом кадре и отдельных вырезках головы/торса. Неоднозначная привязка и сравнимые конфликтующие признаки дают unknown. Недавний результат можно кратко показать, но он не подтверждает тревогу без нового наблюдения. В live и результатах записей есть отдельная панель с оценками и причинами. Дополнительные дообученные `ppe-head.onnx`, `ppe-vest.onnx`, `ppe-head-classifier.onnx`, `ppe-torso-classifier.onnx` подключаются из `data/models` после проверки; notebook экспортирует нужные имена и metadata.

Готовый самодостаточный notebook: [notebooks/LinQ-PPE-Kaggle.ipynb](notebooks/LinQ-PPE-Kaggle.ipynb). В Kaggle включить GPU и Internet, добавить подготовленный корпус как приватный Dataset. Сначала smoke-режим, затем full. Notebook сохраняет last-checkpoints, обучает детекторы и ResNet152-классификаторы, выбирает веса по validation, экспортирует ONNX и train-калибровку. Результаты smoke не устанавливать в рабочий сайт. 24.10 все пять задач прошли короткую проверку на Kaggle T4 x2; полное обучение запущено отдельной [приватной версией №1](https://www.kaggle.com/code/yathebest/linq-ppe-full-training-2026?scriptVersionId=361611151). Состояние на момент проверки и ограничения: `docs/kaggle-launch.json`; это запись запуска, не утверждение о завершённом обучении или точности.

Воспроизводимая подготовка данных:

```powershell
python -m pip install gdown==5.2.0 pyyaml==6.0.3
python scripts/download_ppe_data.py --sources construction site_safety shwd
python scripts/download_ppe_data.py --sources hardhat_vest --root data/datasets/ppe-extra-sources
python scripts/prepare_ppe_data.py --extra-root data/datasets/ppe-extra-sources --output data/datasets/ppe-expanded
python scripts/pack_ppe_data.py --data data/datasets/ppe-expanded --sources data/datasets/ppe-sources data/datasets/ppe-extra-sources --output linq-ppe-training-data.zip
```

Архивы содержат 33 963 изображения; 33 939 имеют найденную разметку. Удалены 3 998 повторов, исключены 5 382 изображения с недостаточной для выбранных задач разметкой и 271 изображение, не давшее пригодных crop. Осталось 24 288 уникальных изображений: train 14 687 / val 4 315 / test 5 286. Детектор людей: 2 910 train, голова/каска: 6 438 train, жилет: 2 020 train. Остальные источники дают явно размеченные classifier crop. После фильтрации осталось 108 416 crop (95 297 головы и 13 119 торса); 50 669 отклонены. Crop не считаются новыми независимыми изображениями. Итоговые размеры - `docs/ppe-dataset-summary.json`, проверка split - `docs/ppe-dataset-check.json`.

Корпус не объявляется четырёхкратным расширением 68 253 upstream train-изображений: для этого требуется 273 012 пригодных уникальных train-изображений. В HardHat-Vest неоднозначные `head/person` не используются как отрицательные классы; явно отмеченные helmet/vest пригодны для положительных crop после проверки. SH17 опционален и имеет CC BY-NC-SA 4.0; лицензии и первоисточники всех данных сохранять.

Точное совпадение графа с SDK проверяется командой ниже. **Успешный ONNX preflight не равен компиляции или запуску платы.** Результат и стадии - в `docs/yolo12m-compatibility.json`.

```powershell
python scripts/check_linq_compatibility.py --model data/models/yolo12m.onnx
```

В отдельном Linux x86_64 / Python 3.12.11 с Framework 2026.9.45 добавить `--compile --calibration <train-only.npz>`. Используются документированные узлы разреза, FP16 Reduce, PIECEWISE_LUT Swish, пресет O1. COCO YOLO12m уже прошла SDK-компиляцию: получена `.tpu`-программа, калибровка на 8 реальных train-кадрах проверяет только тракт. Запуска на плате и измерения точности после квантования ещё нет. Полный порядок, окружение и оговорки - [docs/linq-port.md](docs/linq-port.md). P/R/F1 >0.95 не гарантируется размером модели или количеством файлов.

На Windows с установленным PyTorch CUDA 12 дополнительный ONNX-конвейер можно ускорить: `python scripts/setup_onnx_gpu.py`, затем перезапустить сервер. ORT GPU 1.20.2 устанавливается изолированно в `data/cache/ort-gpu-cu12`; глобальный CPU runtime и Linux SDK не меняются. ORT 1.27+ по умолчанию использует CUDA 13, поэтому здесь не подходит. `SAFETY_ONNX_DEVICE=cpu` принудительно выбирает CPU. Фактический provider указывается в отчёте сеанса. Замер 33 мс относится к одному прогретому PPE-детектору, не ко всему конвейеру.

Репозиторий: https://github.com/yathebest/mosprom2026. Основная локальная папка: `C:\Users\User\Desktop\mosprom2026`.

Весовые файлы хранятся в Git LFS. После клонирования установите Git LFS и выполните `git lfs pull`; без загрузки реальных весов вместо LFS-указателей детекция работать не будет. В Git входят код, модели, выбранные открытые учебные примеры и документация. Локальная БД, записи/клипы камер, полные датасеты, кеши и учётные данные исключены.

Локальное приложение промышленной видеоаналитики с двумя режимами: непрерывный прямой эфир с камеры и анализ загруженных записей. Базовые сценарии: опасная зона, быстрое перемещение, возможное падение и длительное лежание. Добавлены экспериментальные детекторы касок/СИЗ, телефона, огня/дыма, курения и техники, а также зоны ограждений, груза, конвейера и высоты. Точные условия и ограничения каждого сценария — в `docs/scenarios.ru.md`.

**Статус:** локальная реализация и проверки готовы; обязательный запуск на LinQ TPU ещё не выполнен. Цель качества >0,95 не достигнута: независимый тест падений дал Precision = Recall = F1 = 0,90. Подробности и все ограничения — в `docs/validation.md` и интерфейсе «Качество модели».

## Запуск

Откройте `start.cmd`, затем http://127.0.0.1:8765. На этом компьютере люди, поза и падения используют RTX 4060 Laptop 8 ГБ / PyTorch CUDA; дополнительные ONNX-детекторы могут использовать изолированный CUDA runtime из инструкции выше, иначе CPU. Включение всех моделей и crop-проходов увеличивает задержку. Фактические P95 и число обработанных кадров показаны в каждом сеансе. VPN для локального режима не нужен. Секреты стенда в проект не входят.

Для общего демо после клонирования запустите `start-demo.cmd`: он создаст локального администратора `demo-admin` с паролем `LinQ-Demo-2026!`. Данные входа и подробная инструкция для коллег — `DEMO-ACCESS.md`. Обычный `start.cmd` не создаёт демоаккаунт автоматически.

Для индивидуальной установки вместо демо выполните `python scripts/create_admin.py` и задайте собственные реквизиты. Администратор платформы одобряет заявки, сам создаёт предприятия и приглашает их администраторов. Сейчас приглашения работают в режиме имитации: ссылка показывается администратору, действует 60 секунд, используется один раз и заменяется при повторной отправке. SMTP заморожен до настройки сервера — `docs/admin-invitations.ru.md`. Прежние данные сохранены в предприятии «Локальный проект». Матрица прав — `docs/access-control.ru.md`.

## Два режима

**Прямой эфир.** Откройте «Прямой эфир», выберите RTSP/HTTP-камеру либо веб-камеру/USB-устройство, укажите название и правила, начните эфир. Для устройства браузер запросит разрешение; аудио не запрашивается. На localhost поддерживается безопасный контекст браузера. Если встроенный браузер не предоставляет устройства, используйте Chrome/Edge.

Для зон сначала получите кадр. Открытый блок «2. Зоны на кадре» показывает сам кадр, число выбранных точек, назначение и сохранённые полигоны. Отметьте минимум три вершины и нажмите «Сохранить зону»: правило включится автоматически. Кнопка «Разметить зоны на кадре» переводит прямо к редактору. Камеру предпросмотра можно сразу отключить отдельной кнопкой — статический кадр остаётся для разметки, запуск эфира не требуется. Отмена незавершённого запроса камеры и ошибки воспроизведения освобождают полученные медиатрэки.

Изображение с детекцией показывается через MJPEG. Входная очередь хранит только последний кадр, чтобы обработка не накапливала старые кадры. Анализ ограничен примерно 10 кадрами/с; пропуск промежуточных кадров ожидаем. Эфир работает до остановки или потери источника. Доступны два одновременных эфира. Это не испытание промышленной отказоустойчивости; автоматического переподключения нет.

При событии появляется алерт с паттерном, камерой, временем получения кадра и таймингами от начала эфира. Буфер сохраняет 3 секунды до тревоги и 4 после; экспорт H.264 идёт отдельно, эфир продолжает работать. В «Видеопроисшествиях» видны состояния записи/экспорта/готовности, фильтры и скачивание MP4. При ранней остановке сохраняется доступная часть клипа с явной пометкой.

**Анализ записей.** Загрузите видео или выберите учебный URFD-пример. Пройдите четыре шага: источник, сценарии, зоны, проверка. После анализа доступны размеченное видео, клипы, события и JSON-отчёт. До двух файлов анализируются параллельно. Видеофайлы должны иметь постоянный FPS; лимиты — 500 МБ, 4K, 60 минут.

## Качество и границы применимости

URFD: скачаны 70 последовательностей (30 падений, 40 обычных действий), RGB-половины авторских превью. Разделение заранее зафиксировано: 40 обучение / 10 выбор настроек / 20 итоговый тест. Кадры одного ролика не пересекаются между частями. Независимость по участникам подтвердить нельзя. Это бытовые сцены 320×240, не промышленный тест.

На финальном тесте: 9 TP, 1 FP, 1 FN; event Precision/Recall/F1 = 0,90. На отдельных размеченных кадрах: Precision = 1,00, Recall = 0,442, F1 = 0,613. Метрики относятся только к указанной версии модели и сценарию падения. Уверенность кадра, FPS и доля подтверждений оператором не заменяют качество распознавания.

RGB-классификатор оценивает всю сцену, не назначает лежащего конкретному человеку и не доказывает причину падения. Нужны дополнительные данные с целевых камер, разные участники/ракурсы и сложные отрицательные примеры. Для новых сценариев добавлены модели и временные правила, но независимое качество не измерено. Переноска покрыта частично: только сильный наклон с распознанной ручной кладью. Реальная высота, масса груза, произвольные коробки и правильность крепления страховки не определяются.

Метрическая скорость корректна только для неподвижной камеры и выбранной плоскости пола. Без калибровки показывается относительная скорость в видимых ростах/с. Это не отдельный проверенный классификатор бега. При сильном перекрытии трекер может ошибиться; гарантии устойчивой идентичности нет.

Лайв проверен на двух локальных HTTP MJPEG-источниках. Физическая веб-камера и реальные RTSP-камеры отдельно не испытаны. Время live-события основано на времени получения кадра сервером; задержка самой камеры и сети отдельно не измерена.

## Проверки и воспроизведение

Практические заводские проверки, принятые/отклонённые кандидаты и ограничения метрик: [журнал проверки](docs/factory-validation.ru.md). [PDF решений за 24 октября 2026](output/pdf/LinQ-decisions-2026-10-24.pdf) фиксирует стратегию и состояние работ на указанное в документе время.

```powershell
python -m pytest -q
node --test tests/test_camera_preview.cjs
python scripts/prepare_urfd.py --all
python scripts/export_onnx.py --opset 12 --size 640
python scripts/export_body_onnx.py
```

Скрипт подготовки загружает авторские MP4 и CSV-аннотации, выделяет RGB. Полный набор есть локально; переносимый ZIP содержит четыре демо и манифест, остальное можно скачать.

Исходное обучение: `python scripts/train_fall_classifier.py --epochs 18`. Существующие оценённые веса защищены от случайной перезаписи; для нового эксперимента используйте копию проекта. Выбор порогов: `python scripts/evaluate_fall.py --split validation`. Итоговый тест запускается `--split test` один раз и отказывается молча перезаписывать существующий отчёт. Новый эксперимент требует нового независимого теста; нынешние 20 роликов уже раскрыты.

## Файлы

`app/live.py` — непрерывная детекция и клипы; `app/video.py` — файлы; `app/core.py` — временные правила; `app/inference.py` — сменяемый backend; `app/operations.py` — очередь и разметка; `app/scenario_models.py` — ONNX и crop телефона; `app/scenarios.py` — дополнительные правила; `app/static/` — интерфейс; `docs/coverage.json` — матрица требований; `docs/linq-port.md` — перенос; `docs/validation.md` — проверки; `docs/quality_report.json` — независимый тест; `docs/reference/` — исходные PDF.

Видео и результаты хранятся на этом компьютере. URL сетевых камер остаются в памяти, без сохранения в БД/экспорт. Сервер слушает только 127.0.0.1. Для сетевого развёртывания нужны отдельная аутентификация и контроль доступа.
